# GitHub, Revisão e Publicação

> **Papel deste documento:** definir o que será ensinado, praticado e avaliado.  
> A condução minuto a minuto, falas sugeridas, respostas esperadas e intervenções ficam no [script do professor](scripts/modulo-03-aula-04-github-e-colaboracao.md).

## Objetivo da aula

Publicar o primeiro projeto no GitHub e compreender como branch, proposta de mudança e revisão apoiam colaboração.

Ao final, o aluno deverá conseguir:

- distinguir repositório local e remoto
- publicar um histórico com segurança
- explicar branch e revisão
- produzir README executável por outra pessoa
- registrar uma proposta de melhoria verificável

## Conteúdos e conceitos

### Local e remoto
- Git local
- GitHub remoto
- sincronização não é automática

### Branch e proposta
- branch isola linha de trabalho
- pull request comunica mudança
- revisão antes da integração

### README e acessibilidade
- contexto
- como executar
- limites e evidências

## Demonstração planejada — Publicar e revisar uma melhoria de documentação

1. Criar/conferir repositório remoto.
2. Conectar `origin`.
3. Enviar histórico.
4. Criar branch de documentação.
5. Alterar README.
6. Comparar mudança e preparar proposta de revisão.

**Resultado pedagógico esperado:** o aluno consegue explicar compartilhamento e revisão sem usar push forçado como atalho.

## Dinâmica em grupo — Revisão de README

**Cenário:** Uma pessoa publica instruções que funcionam apenas se o usuário já souber em qual pasta executar.

1. Identificar o problema de documentação.
2. Propor mudança em branch.
3. Escrever descrição com problema, mudança e verificação.
4. Outra dupla revisa sem editar diretamente.

**Entrega esperada:** proposta de mudança revisável

**Critérios:** problema claro; mudança focada; verificação possível; limites honestos.

## Exercício individual

Verifique se outra pessoa consegue entender e executar seu projeto. Registre a URL ou pendência de acesso e escreva uma descrição curta de uma melhoria: problema, mudança e como verificar.

**Entrega:** link/verificação do repositório + descrição de proposta

**Critérios:** acesso conferido; README suficiente; proposta clara; sem inventar execução.

## Perguntas de verificação

- Git e GitHub são a mesma coisa?
- O que uma boa descrição de PR precisa explicar?
- Por que README faz parte do projeto?

> As respostas esperadas e intervenções ficam exclusivamente no script do professor.

## Tarefa para casa

4. Entregar `m03-aula-04-revisao.md` e organizar a entrega do módulo.

**Entrega:** repositório verificável + revisão documentada
