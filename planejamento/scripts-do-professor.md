# Scripts do Professor — Índice e Regras de Condução

## Papel do script

Os 32 encontros dos oito módulos e as duas aulas do bônus possuem um **Roteiro de Aula** e um **Script do Professor**.

A relação oficial é:

> **E-book = o que o aluno aprende e revisa**  
> **Roteiro = o que aquela aula ensina, pratica e avalia**  
> **Script = como o professor conduz exatamente aquela aula ao vivo**

O script **não é uma segunda versão da aula**. Ele operacionaliza o roteiro.

## Ordem de uso pelo professor

Antes de cada encontro:

1. consulte a [trilha e índice](trilha-e-indice.md) para localizar a aula;
2. leia o **Roteiro de Aula** para compreender objetivo, conteúdo, demonstração, atividade e entrega;
3. revise no **E-book** apenas os conteúdos correspondentes àquela aula;
4. abra o **Script do Professor** e percorra os 90 minutos;
5. prepare ferramentas, exemplos, arquivos e ambiente;
6. confira a atividade/caderno de prática que será entregue;
7. durante a aula, use principalmente o script como guia de condução.

O texto do script é apoio. As falas sugeridas podem ser adaptadas ao estilo do professor, desde que conceitos, exemplos centrais, critérios e entregas permaneçam coerentes com o roteiro.

## Invariante Roteiro → Script

Antes de considerar um par válido, conferir:

| Elemento | Regra |
|---|---|
| Tema | O script trata exatamente do mesmo tema do roteiro |
| Objetivo | O script repete e operacionaliza o objetivo do roteiro |
| Conteúdo | O script não introduz pré-requisito que o aluno ainda não estudou |
| Demonstração | A demonstração central é a mesma planejada no roteiro |
| Dinâmica | A prática em grupo é a mesma do roteiro |
| Exercício individual | Avalia o mesmo resultado de aprendizagem |
| Tarefa | A tarefa e a entrega são equivalentes |
| Perguntas | O script contém respostas/intervenções para as perguntas de verificação do roteiro |
| Nível | A linguagem respeita o momento da trilha |
| Evidência | Gabaritos e respostas de referência ficam somente no script |
| Tempo | O recorte cabe em até 90 minutos sem transformar pausa em conteúdo |
| Continuidade | A ponte para a próxima aula corresponde à trilha real |

Microexemplos podem ser acrescentados no script para explicar uma ideia, mas não podem substituir silenciosamente a demonstração, atividade ou entrega definidas no roteiro.

## Progressão didática de linguagens

A trilha usa:

- **Python** como linguagem didática principal no Módulo 2 — Lógica de Programação;
- **JavaScript** como primeira comparação de sintaxe no Módulo 3, mostrando que a lógica é transferível;
- **TypeScript** como evolução contextual e ponte para automação, especialmente ao discutir ferramentas como Playwright;
- nenhuma aula deve exigir domínio inesperado de JS/TS antes de essa transição ser apresentada.

## Estrutura de até 90 minutos

| Intervalo | Etapa |
|---|---|
| 00–08 | Abertura e diagnóstico |
| 08–25 | Conceitos e exemplos |
| 25–45 | Demonstração guiada |
| 45–50 | Pausa |
| 50–65 | Dinâmica |
| 65–77 | Exercício individual |
| 77–85 | Correção e dúvidas |
| 85–90 | Fechamento e tarefa |

A estrutura de tempo é comum; **a experiência pedagógica não deve ser genérica**. Uma aula de Git, uma de Produto, uma de QA e uma de entrevista podem usar o mesmo relógio, mas precisam de atividades próprias do tema.

## Uso da gravação

A gravação é material de revisão, não prova de aprendizagem. Oriente o aluno a:

1. localizar o trecho em que surgiu a dúvida;
2. rever demonstração/correção;
3. refazer a atividade com outra entrada ou situação;
4. comparar primeira versão e revisão.

Avaliação deve se apoiar em artefato, explicação e evidência, não apenas em percentual de vídeo assistido.
